# 学术文献综述工作流：实现与使用

> 历史版本说明：逐篇必须确认的流程已被替换。当前使用说明见 [相关文献与方向多选](direction_selection_workflow.md)。

本轮已在本地 `./academic-research-agent` 实现正式代码。核心产物是**基于用户采用文献、带可追溯证据的学术综述大纲**。不是完整论文，也不把模型判断等同于人工科学核实。

## 1. 打开应用

在 PowerShell 中运行：

```powershell
Set-Location 'path/to/academic-research-agent'
$env:PYTHONIOENCODING='utf-8'
$env:MOCK_MODE='0'
.\.venv\Scripts\python.exe -m streamlit run streamlit_app.py
```

按终端显示的本地地址进入网页。选择厂商、模型，输入自己的 Key，阅读费用提示后点击“测试连接”。这一步会发送一次有输出上限的真实生成请求；加载模型列表与验证生成仍然分开。研究过程也会使用该用户的 Key 产生模型费用。

只检查操作流程时可在侧栏选择离线演示；演示使用合成文献，不调用付费 API，不代表研究质量或连接验证成功。

CLI 使用同一个工作流：

```powershell
.\.venv\Scripts\python.exe main.py
```

## 2. 真实使用场景

示例研究问题：**“检索增强生成在医学问答中的幻觉控制：方法、评价指标与适用边界”**。这里的主题只是输入示例，下文没有声称已为这个主题完成真实文献检索。

### A. 提交研究问题

在输入中写明对象、任务、重点和必要约束；例如限定医学问答，比较幻觉控制方法，关注评价指标，限定 2022–2026 年。模型先拆分问题并保留约束，随后检索 arXiv、Crossref；Semantic Scholar 用于后续用户触发的补检索。检索失败、限流和真实空结果分别记录。

先阅读审核页中的检索计划，确认英文检索表达没有改变原问题。范围不对时可展开“调整研究范围”，输入新的范围后重新检索；原历史保留，预算累计。

### B. 逐篇决定采用文献（第一确认点）

每篇卡片显示标题、作者、年份、摘要、机器相关性判断与理由，以及原文页面、DOI、开放全文链接。来源没有可用链接时不编造地址；只有 DOI 时生成 DOI 解析链接。

每篇默认**待定**，由你选择“采用／排除／待定”。机器排除的论文也能采用，但必须填写理由，例如“包含与主流观点相反的结果，适合作为争议部分证据”。机器判断不因此改写。

“机器接受 0、未判断 5”与“5 篇均不相关”含义不同。模型错误、预算不足或未进入模型筛选短名单的候选会保留为未判断；演示数据明确标记 demo。目标数量默认 5，不代表质量保证，也不限制你在证据不足时接受部分大纲。

可在对应卡片上传本地 PDF。点击“确认采用集合”后才处理文献；排除和待定项不会进入证据卡片或大纲。首版同时采用上限默认 10 篇。

### C. 检查证据卡片

每篇已采用文献包含六个字段：研究问题、对象与条件、方法、作者发现、作者明确说明的局限、与当前话题的关系。话题关系标为系统综合，其余是对作者陈述的提取；它们仍是模型辅助提取。

每项区分：

| 状态 | 含义 |
| --- | --- |
| found | 在提供给提取器的文本中提取到，并关联原文证据 ID；尚不等于独立科学核实 |
| not_found_in_processed_text | 已处理的文本中没有找到，不代表整篇论文或整个领域不存在 |
| not_checked | 未执行或未完成检查，例如缺文本、调用失败、预算不足 |

证据保留 paper ID、chunk ID、原文摘录和位置。全文可有页码；摘要明确标注 `abstract; no page`，不会编造实验细节或页码。不支持扫描件 OCR、图表理解或复杂公式解释。

### D. 审核学术综述大纲（第二确认点）

大纲包含问题与范围、实际检索与选择、概念框架、按主题／方法组织的比较、分歧与条件、未来问题、结论边界。模型可增加主题子节，不要求一篇文献对应一节。

每个节点有标题、写作目的、问题关联、观点、证据与反证、条件、缺口、待写任务和状态。观点区分作者发现、系统综合、假设与用户观点。事实性观点必须引用当前已采用集合中的证据。

在界面中可修改标题、顺序、目的和写作任务；高级 JSON 编辑器可修改观点、条件和引用。点击保存后才替换当前版本，并重新检查。无效结构、未知证据 ID 或摘要冒充全文时保留原版本并报错。

程序检查引用映射、证据层级、问题覆盖和重复标题；辅助模型检查观点是否被引文支持。篇章连贯性、语义重复和科学完整性没有自动可靠检查，明确保留 `not_checked`。不能仅因一条引用存在就认为观点成立。

### E. 处理缺口

缺文献时显示建议检索问题，**先选缺口，再点击补检索**。不会在后台自动发起。新候选重新回到逐篇确认页，尚未采用前不能进入大纲。原采用集合和旧大纲在等待期间保持可用。

缺全文时返回文献页补充 PDF；观点支持不足时可收窄表述、比较反证，或选择建议的补检索。首版补检索最多 2 轮，模型调用、请求和 token 预算累计，全文处理尝试额度也不随循环重置。达到上限可结束或接受带缺口的现有大纲，不会自动通过。

已保存的用户节点文字会保留。移除其引用文献或改变原文后，旧引用会失效；保留的文字标为用户观点并提示重新补证据，不继续冒充已支持的作者发现。

### F. 接受、保存和恢复

可接受当前大纲或结束并保留草稿。存在缺口时记录 `accepted_partial`；不会把尚未检查或支持不足的判断改成通过。

在任一确认页展开“保存项目与导出”，下载：

| 文件 | 内容 |
| --- | --- |
| outline.md | 大纲、状态、采用文献链接、原文证据与位置、检查结果与缺口 |
| evidence_cards.csv | 六字段卡片、类型、状态、证据 ID 和摘录 |
| paper_decisions.csv | 机器判断、人工采用决定、理由与决定来源 |
| project.json | 可恢复的项目状态、采用集合／大纲版本、历史、预算和已处理文本 |

恢复时在开始页选择 `project.json`，配置并验证自己的 Key，再点击“打开项目”。恢复直接回到保存的文献审核或大纲审核位置，不自动重跑检索、生成或重新宣称旧判断已被验证。只恢复当前采用集合的已处理文本缓存；替换 PDF 需要重新上传。Key、SDK 客户端和私有 PDF 路径不写入项目。

CLI 在任一审核点选择 `[6]` 保存项目。恢复命令：

```powershell
.\.venv\Scripts\python.exe main.py --project 'C:\path\project.json'
```

CLI 修改观点时可复制项目文件、编辑 `state.outline`，在大纲审核选择 `[5]` 读取该 JSON。程序先验证再保存修改。完成后选择保存，另导出四个文件到 `.research_runs/<run_id>/`。

必须主动保存项目；内存中的 MemorySaver 不是未保存项目的重启恢复。当前没有自动云同步、登录或多人服务部署。

## 3. 本轮实现与测试边界

新增模块：`review_workflow.py`、`projects.py`、`review_ui.py`、`review_cli.py`。更新共享 graph/state、标题与链接处理、筛选缓存、两种入口、结构化任务 schema、离线 demo 和批量评价的确认来源标记。

离线覆盖两次人工确认、默认不采用、推翻排除需理由、只处理采用文献、缺口手动触发、新候选未批准、用户修改保留、旧引用失效、全文和摘要位置、恢复时预算保留、跨轮次全文额度、错误项目／凭证拒绝、模型失败的部分结果，以及网页／CLI 操作和导出。批量评价与演示中的自动决定单独标记，不伪称真实人工标签。

本轮没有真实付费模型请求、公开文献 API 请求或模型权重下载。之前已验证的 DeepSeek `deepseek-flash` 仅通过过一个小额连接生成请求；这不等于本轮完整学术综述流程已用真实文献和模型验证。OpenAI、Anthropic 没有 Key，仍未真实验证。检索相关性、提取准确性和大纲学术质量仍需你用真实主题复核；没有声称速度或研究质量已通过基准提升。

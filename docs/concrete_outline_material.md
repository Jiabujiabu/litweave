# 大纲中的具体文献内容与比较支持

本轮根据真实使用反馈细化大纲内容，保持原来的“相关文献 → 方向多选 → 一份整合大纲”流程。

## 前端变化

- 移除完成页的 **Evidence and check details**，同时移除大纲审核中的技术检查 JSON、内部证据卡片面板和 JSON 大纲编辑器。
- 论文标题、原文链接与可读的出处继续保留。技术检查仍在后台执行，并可随项目、证据文件导出。
- 通过普通输入框修改标题、顺序、观点和个人笔记，不需要读代码。

## 每节提供什么

“研究问题与综述范围”会写明当前问题和所选方向，并列出已经提取到的研究问题、对象、条件及数据来源。主题比较部分会直接提供各文献中的方法流程、数据与实验设置、评价指标、作者发现及作者明示的局限。

每条内容附论文名称、来源链接，以及实际可定位的摘要或 PDF 页码。开放全文可直接跳到 PDF 对应页；只有摘要时明确写“摘要”，不编造页码或实验细节。

文献对照表里的内容由 agent 根据已经提取到的材料填写。例如同一列并排放置各文献的方法、数据或指标，再给出本节采用的具体内容。表中会保留各研究自己的实验条件和结果；不会仅凭不同数据集或不同指标的分数判断哪种方法更好。

相同的对照表不会在每个方向重复铺开。后续节会引用同一组研究，突出本节的具体内容。未来问题部分仅整理作者明确说明的限制或待解决问题；不自动补写用户的独立立场。

## 信息不足时的区别

| 显示内容 | 含义 |
| --- | --- |
| 已列出具体内容并附来源 | 已从提供给提取器的文本中整理到；仍可点击原文核对 |
| 当前已读文本未提及 | 这一轮实际处理的文本没有找到，不能据此断定整篇论文未报告 |
| 尚未提取 | 尚未完成该字段的提取或判断 |
| 原文摘录（尚未完成字段提取） | 保留可读原文供查看，不将它伪装成已经提取好的方法、数据或结果 |

移除了“围绕研究问题组织证据”“根据证据补充比较、转折与个人判断”等通用占位句。旧项目显示时也会替换已知占位目的，保留用户自己写的内容。

后台若判定引文不足以支持某项，正常页面会用简短文字标明支持不足，不把它列成可写的已支持结论；部分支持会提示核对范围。隐藏技术面板不等于隐藏这些有实际影响的结果。

## 兜底与恢复

详细材料由既有证据卡片直接组装，默认不为表格增加新的生成调用。方法、数据、指标等有效字段可以独立保留；某一字段格式或引用失败不会让其他有效字段全部消失。

章节综合调用若遇到原有的请求、模型或上下文额度限制，会明确标为未完成，同时保留已经提取到的具体内容与出处。不会提高额度，不会将 mock 当成真实成功。相同事实在不同章节出现时会复用辅助检查结果。

旧六字段项目可以导入，新增的“数据”和“评价指标”会保留为尚未提取；如需提取这些新增内容，可返回方向页重新生成。保存项目仍不包含 API Key 或 SDK 客户端。

## 使用

重启应用后新建研究，按原流程选方向生成大纲。已有项目也可导入，直接显示已有字段能支持的具体材料。

```powershell
Set-Location 'path/to/academic-research-agent'
$env:PYTHONIOENCODING='utf-8'
$env:MOCK_MODE='0'
.\.venv\Scripts\python.exe -m streamlit run streamlit_app.py
```

本轮没有使用用户的 Key 发起付费请求。验证采用原创建的合成文献、离线 SDK 替身和 Streamlit AppTest；具体提取质量、论文对照的科学充分性仍需真实主题验证。最近真实请求的脱敏记录只有计划、筛选、方向与卡片调用，没有大纲请求记录；仅据此无法确认先前未生成章节综合的具体原因。

# 修复：只有首篇文献有效，其余均显示“尚未提取”

## 定位到的问题

1. 逐篇文献提取复用了面向研究方向的全局 top-k 证据。少数排在前面的论文可反复占用片段额度，后面的论文虽然在文献列表里，却没有分配到输入文本。
2. DeepSeek 的 JSON 对象请求没有发送本地 JSON Schema，但原来的额度估算把整份 Schema 也算进去了。逐篇提取还统一预留 4096 输出 token，容易提前耗尽本轮预留额度。
3. 未执行、没有材料和提取失败均可能留下空字段；空白或不完整卡片也可能被缓存，页面因此统一出现“尚未提取”。

最近真实运行的脱敏日志只记录到一次卡片提取请求。没有保存到该会话的完整项目状态，因此没有声称已确认那一次运行的唯一触发条件；以上处理链路问题已在离线数据中复现并修复。

## 已修改

- 每篇已纳入当前方向且有可读文本的论文，先分配一份独立材料，再分配额外片段。逐篇输入不再依赖全局 top-k 排名。
- 优先使用可读摘要，必要时补充正文片段；短片段使用新的内容哈希和 ID，保留真实摘要／PDF 位置。
- 只为实际发送的格式参数预留额度。逐篇提取和辅助检查的输出上限分别降到 2048、384，若用户配置更低则采用更低值。总请求、模型和 token 上限不增加。
- 空卡片和未完成卡片不再算作已完成缓存。已经成功的字段保留，后续单篇失败不会中断其他文献。
- 仅对当前方向中的研究建立比较行；未纳入该方向的论文不会以空白对照行出现。

## 现在如何处理旧结果

重启应用后，可以在大纲审核页或完成页点击 **“重试未完成的文献提取”**。保存的旧项目也可以导入后重试。

重试使用已保存的摘要和已处理正文，只补未完成文献／字段，复用仍有有效来源的已完成结果，不重新搜索、不重新下载，也不重置本轮预算。CLI 对应大纲页选项 `[7]`。

如果按钮因额度不足或重试次数上限而不可用，会明确说明原因，仍可保存现有结果。没有可读摘要／正文的文献需要补充 PDF；无法靠重试制造不存在的资料。

| 新提示 | 含义与处理方式 |
| --- | --- |
| 当前已读文本未提及 | 确实执行了提取，但当前分配的文本没有该信息；可补充全文 |
| 没有可读摘要或正文 | 需要添加可读材料 |
| 文本分配额度不足 | 该轮没有给该论文分配到文本，不等于论文没有相关内容 |
| 本轮模型或 token 额度不足 | 没能完成调用，不会记作提取成功 |
| 返回字段或引用无效 | 仅保留已验证有效的字段，可重试其余项目 |
| 模型请求失败 | 保留其他论文的结果，允许在剩余额度内重试 |

## 验证边界

137 项离线测试通过，其中 17 项专门覆盖本问题。包含：旧全局检索只覆盖首篇的复现；5／10 篇长文本的公平分配；10 篇在原有总预算内通过本地 SDK 替身逐篇调用；单篇失败、预算不足、错误引用、缓存、项目恢复及网页／CLI 重试。

这些是离线功能验证，不是新的付费模型测试，也没有测出真实文献的提取准确率提升。本轮没有使用用户的 Key 发起网络生成请求。

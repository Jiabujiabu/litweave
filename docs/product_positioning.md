# 产品定位与差异化分析

结论：目前有可用的工程差异，但尚未证明检索/筛选质量优于通用 AI。仅提供“输入话题→返回论文→生成综述”，吸引力有限。更值得形成产品的是一个能让研究者逐篇核对取舍、整理原文证据并复用结果的文献筛选工作台。

## 不应作为独有优势宣传的内容

通用 AI 已经具备联网搜索、来源引用和多来源研究报告工作流。以 ChatGPT 为例，官方文档说明了网页搜索的结果/引用，以及深度研究中的多来源调查和报告复核。因此，不能用“通用 AI 只能聊天、不能查文献”作为卖点。

来源：[OpenAI 官方说明：Web search](https://learn.chatgpt.com/docs/web-search)。本文没有对各家 AI 做统一实测，也不据此宣称所有产品的实现细节相同。

多来源、RAG、混合检索、LangGraph 也属于实现方法。用户通常更在意是否少漏关键论文、为什么保留这篇、证据能否打开、整理结果能否复用。

## 当前项目实际具备什么

| 能力 | 当前状态 | 可以给用户的具体价值 |
| --- | --- | --- |
| arXiv/Crossref/Semantic Scholar 元数据规范化、DOI/arXiv 去重和来源溯源 | 已实现 | 少重复整理同一篇论文，保留来源与版本关系 |
| 原问题、约束、子问题与有界补充搜索 | 已实现，但计划和筛选仍受模型判断影响 | 研究方向可检查，明确显示数量或覆盖不足 |
| 逐论文筛选状态和理由 | 后端有记录；网页展示/导出不完整，且整批未判定问题待修 | 这是需要补齐的关键用户价值，目前不应宣传为成熟审核台 |
| 原文片段、论文/证据 ID、页码或仅摘要标记 | 已实现，PDF 解析有限制 | 用户能核对关键结论的具体依据，知道证据级别 |
| 引用映射检查与辅助模型支持检查 | 已实现；不是人工事实认证 | 区分“论文存在”和“证据支持这个结论”，保留失败与未检查状态 |
| 用户选择服务商/模型并使用自己的 Key | 本轮已实现并通过离线隔离测试 | 账户与模型选择权在用户手中，运营者不垫付模型 API 费用 |
| 固定快照、配置、trace 和消融评测工具 | 开发工具已实现，尚非完整网页历史工作区 | 有条件排查策略变化，后续可支撑可复现的对比 |
| 优于通用 AI 的相关性、准确性或成本 | 尚未证明 | 需要独立人工评测，不能从测试通过或历史数字推导 |

这些是当前项目的工作流特点，不表示其他产品不能提供类似能力。可持续优势需要来自稳定体验、领域积累和验证结果。

## 建议定位

**面向 CS/AI 学生和研究者的文献筛选与证据整理工作台：帮助用户解释每篇论文的取舍，并把综述中的结论定位到原文。**

先服务要写 related work、开题调研、准备组会的用户。他们需要可交付的论文清单和证据整理，而不仅是一次聊天答案。BYOK 更适合愿意配置模型账户的技术用户；它增加了进入门槛，本身不是独占优势。

## 用户为什么可能专门打开这个工具

建议围绕一个具体任务设计下一版：

1. 用户写明研究问题，并确认纳入/排除标准（任务、年份、对象、证据要求）。
2. 系统把候选论文列成审核表，逐篇显示相关性状态、原文依据和简短理由。
3. 用户能够保留、排除或标记不确定；系统记录人工修改，不替用户批准。
4. 用户点击结论即可查看支持原文与页码，能看清仅摘要、部分支持和未检查。
5. 一次导出候选取舍记录、文献清单和证据表，继续用于写作和复核。

这里的“独立纳入排除表单、逐篇人工保留/排除、完整审核表、CSV/BibTeX 导出”等是建议功能，当前尚未全部实现。当前已有整轮审核、Markdown 报告和证据 JSON。

对于只是随手找几篇入门论文的用户，通用 AI 往往已经够用。这个产品应争取那些需要反复核对、多人讨论或保留研究记录的任务。

## 下一版优先级

**第一优先：修复会损害信任的现有问题。** 标题显示正常；明确区分 accepted/rejected/unjudged；异常条目不拖累整批；补充检索失败不丢失仍有效的旧判定。没有这些基础，宣传更复杂功能难以留住用户。

**第二优先：完成可解释的文献审核表。** 每篇展示状态、理由、命中的子问题、年份排除原因和证据级别；支持逐篇人工修订与导出。让用户一次就能看懂“为什么 0/5”。

**第三优先：把结果变成可复用的研究材料。** 增加统一的证据矩阵，如研究任务、方法、数据集、评价指标、发现和局限，每格附原文依据；信息没有提供时留空，不让模型补造。再增加文献格式导出和任务历史。历史持久化尚未实现。

不建议为了差异化先堆更多 agent、换更大的模型或做复杂前端。先把同一任务的手工核验和整理成本降下来。

## 怎样证明值得用户使用

先做小范围、独立人工评估；比较时固定研究问题与完成标准，记录工具版本和实际调用配置：

- 用户找到并确认前 5 篇直接相关论文花了多久。
- 人工审核的入选论文直接相关比例；未判定和错误另列。
- 用户预先给出的已知关键论文是否被找到，不能冒称全领域召回率。
- 抽查报告结论，原文是否足以支持其任务、范围、数字和限定条件。
- 导出结果能否直接用于后续整理，减少了哪些手工步骤。
- 每次任务实际模型调用、token 和已知费用；不把本地运行或 BYOK 当成免费。

先记录基线和失败样例，再决定产品指标。没有这些结果，目前诚实的表述是“提供专门的、可核对的文献工作流”，不是“比通用 AI 更准确”。

## BYOK 对商业定位的影响

用户为自己的模型 API 账户付费，解决的是运营者垫付推理费用的问题。托管、存储、支持仍有成本。用户为什么愿意额外使用这个应用，必须由可节省的时间、可复用的研究材料和可靠体验来回答。

若后续收费，收费价值可以围绕工作流、整理与协作服务设计，不能把“用户已自行支付模型费”当成产品无需提供额外价值。本文不推定定价、收入或市场需求已经验证。
